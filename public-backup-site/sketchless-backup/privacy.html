Privacy policy

Effective November 2, 2026

This policy covers Sketchless Private Backups, the owner-operated backup utility maintained by @kevincyril, and these public information pages. It describes the implemented workflow; it does not claim that the backup schedule is enabled or that a Google Drive upload has already completed.

Google permission and data accessed

The tool requests only https://www.googleapis.com/auth/drive.file, with offline authorization for unattended backups. This permission allows access to files created by the app or explicitly made available to it. The implementation uses a dedicated folder created by its own OAuth app; it does not request general access to the owner's Drive, Gmail, contacts, calendar or profile.

It reads the backup folder's ID, type, ownership and sharing status; creates backup ZIP files; reads backup file IDs, names and creation times for retention; and downloads uploaded archive contents to verify their SHA-256 checksum. It updates app-specific verification metadata and deletes eligible older verified backup files. It refuses to use a destination folder that is shared or is not owned by the authorizing account.

Backup contents and purpose

The source snapshot includes the Sketchless database's saved sessions, conversations, design specifications, jobs, version history, anonymous ownership identifiers, usage-budget records and artifact metadata, plus successful CAD exports. These may contain private user prompts and design information. The sole purpose of copying this information to Drive is backup, integrity verification and owner-directed recovery.

The archive format excludes runtime configuration and credential files. It does not scrub a secret that someone has themselves written into a prompt or design. The operator must protect archives as private application data.

These service providers process data to provide storage, authorization and job execution, subject to their own terms and policies. People the owner authorizes to administer the private repository or relevant accounts may be able to access the data or credentials through those systems. The tool does not publish backups, upload archives as GitHub Actions artifacts, or commit secrets or archives to source control.

The backup code uses temporary directories for export and restore work and removes them when a run exits normally. Interrupted jobs can leave temporary data until the runner or host cleans it up. This is not a promise of forensic secure erasure. User-created local backup copies remain until the owner removes them.

Retention and deletion

After a local restore check and a verified download of the new Drive upload, the tool marks the upload verified. It keeps the eight newest eligible, verified backup-app ZIPs in the dedicated folder and permanently deletes older eligible files through the Drive API. It does not delete unrelated Drive files. Failed or unverified uploads are excluded from automatic retention and may need manual cleanup. Archives are not subject to a fixed day-based expiration.

Revoking Google authorization stops future API access but does not automatically delete files already in Drive, GitHub repository secrets or local credential files. To stop and remove the setup, disable the workflow, revoke the tool in Google Account connections, delete the backup folder in Drive, remove the private repository's Actions secrets, and remove local credentials and any local archive copies. Deleting a backup does not delete its source records in Neon. Source-data deletion and deletion of existing backup copies must be handled separately.

Sharing and secondary use

Google user data is used only to create, verify, retain and recover the owner's private backups. It is not sold, used for advertising, used for unrelated profiling, or sent by this backup tool to Gemini or other AI services. Google user data is not used to develop, improve or train generalized AI or machine-learning models. The tool's use and transfer of information received from Google APIs adhere to the Google API Services User Data Policy, including its Limited Use requirements where applicable.

Logs and this public website

The backup script reports status, the number of successful versions, archive byte count and retention setting. Its handled failures suppress credential values and provider response bodies. Platform-level logs may contain execution times, job metadata and infrastructure diagnostics. The owner controls access to the private repository and those logs.

These public pages contain no analytics, forms, client-side scripts, Google authorization flow or app-set cookies. They load a local stylesheet. GitHub Pages, the hosting provider, logs visitor IP addresses for security purposes as described in the GitHub Privacy Statement.

Questions and changes

For privacy or deletion requests, use the support email displayed on the tool's Google authorization screen. The maintainer is the owner of @kevincyril. Do not include secrets or private designs in public messages. Changes to data handling will be reflected here with an updated effective date; new uses of Google data require appropriate disclosure and authorization before they begin.
